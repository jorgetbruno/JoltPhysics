# Audit — 2026-08-02

A multi-agent read-only audit of the gem at commit `3e63533`: six reviewers swept one
dimension each (correctness, PhysX parity, editor UX, performance, script/API surface,
robustness), then every candidate finding was re-checked by an independent adversarial
verifier against the cited code. **35 findings, none refuted.**

Baseline for the sweep was KNOWN_ISSUES.md and DIVERGENCES.md, so nothing here is a
restatement of a gap the gem already tracks or a divergence it already justifies.

Severity: **P0** correctness/crash/data-loss a user would hit · **P1** user-visible pain or
a missing piece blocking real use · **P2** quality-of-life or debt · **P3** nice-to-have.

### MakeMutableCompound displaces every compound child with a non-zero center of mass (convex hulls, hull groups) - AddShape/RemoveShape silently corrupt body geometry

*correctness · effort: medium*

**Evidence.** Code/Source/Shape/JoltShapeUtils.cpp:601-606 passes subShape.GetPositionCOM() + sourceCenterOfMass as AddShape's local position without subtracting rotation * childShape->GetCenterOfMass(). Jolt stores storedPosCOM = inPosition - compoundCOM + rot*childCOM (Jolt CompoundShape.h:177-180, re-applied in MutableCompoundShape.cpp:208-213), so each re-added child lands at srcLocalPos + rot*childCOM. Jolt convex hulls have non-zero COM (ConvexHullShape.h:54,186). Triggered by JoltRigidBody::AddShape/RemoveShape (JoltRigidBody.cpp:864, 900) and JoltStaticRigidBody::AddShape (JoltStaticRigidBody.cpp:340). Additionally, flattening a single-collider hull-group StaticCompound into per-hull children breaks RemoveShape's 'colliders map 1:1 to sub-shapes' index math (JoltRigidBody.cpp:896-906) and GetColliderIndexFromSubShapeId's colliderCount assumption (JoltShapeUtils.cpp:618-643). Existing tests only exercise single-box bodies (JoltRigidBodyTests.cpp:197-258), where the non-compound path hides the bug.

**Why it matters.** Anyone calling the public AzPhysics::RigidBody::AddShape/RemoveShape on a body built from a mesh-asset collider (multi-hull .joltmesh, VHACD hull group, or entity-space-scaled rotated hull) gets every hull shifted by its centroid offset - collision visibly detaches from the render mesh, and RemoveShape can delete the wrong sub-shape. Same bug class as the just-fixed convex-hull draw offset, surviving in the runtime mutation path.

**Verifier.** Math verified against Jolt v5.6.0 source. CompoundShape.h:177-183 (SetTransform) stores storedPosCOM = inPosition - compoundCOM + rot*childCOM, and MutableCompoundShape::AddShape (MutableCompoundShape.cpp:208-213) re-applies that formula against the new compound's COM. JoltShapeUtils::MakeMutableCompound (Code/Source/Shape/JoltShapeUtils.cpp:594-607) reconstructs the local position as storedPosCOM + sourceCOM, omitting the -rot*childCOM term, so after AdjustCenterOfMass each re-added child sits at its correct position PLUS rot*childCOM. Zero-COM children (centered boxes/spheres/capsules) are unaffected, which is exactly why the only AddShape/RemoveShape tests (JoltRigidBodyTests.cpp:194-258, single-box bodies) pass; convex hulls (nonzero mCenterOfMass, verified in ConvexHullShape.cpp:83) and hull-group/nested StaticCompound children are displaced. The single-collider hull-group case is additionally flattened into per-hull children by the StaticCompound branch, breaking RemoveShape's createdColliderCount+attachedIndex sub-shape math (JoltRigidBody.cpp:894-906) and the collider<->sub-shape mapping GetColliderIndexFromSubShapeId assumes (JoltShapeUtils.cpp:618-643). All three call sites are the public runtime-mutation paths: JoltRigidBody.cpp:864/900 and JoltStaticRigidBody.cpp:340; creation paths are unaffected (the non-compound else branch at JoltShapeUtils.cpp:609-612 round-trips exactly). Severity P1 and medium effort are right: the COM-term fix is a one-liner, but the hull-group flattening needs a mapping decision (e.g. add the whole base as one child).

### Persist collision events: per-manifold heap allocation, contended mutex, an extra full copy, and double dispatch every step — with no check that anyone is listening

*performance · effort: medium*

**Evidence.** Code/Source/Scene/JoltScene.cpp:1825-1838 — OnContactPersisted queues a CollisionEvent for every persisted sub-shape manifold every step (Begin is deduplicated per body pair via TrackContactAdded at 1818, Persist is not, so a compound touching with k manifolds queues k events per step). JoltScene.cpp:1345-1385 — each queueing builds an m_contacts vector (heap alloc) and takes m_collisionEventMutex; Jolt invokes these callbacks from parallel narrowphase jobs, so all workers serialize on one lock. JoltScene.cpp:1280-1343 — the flush swaps the queue into a local (destroying accumulated capacity each step, 1282-1286), then push_back(collisionEvent) at 1309 COPIES every event including its contacts vector into dispatchableEvents, then dispatches each event twice through ProcessCollisionEvent with normal flips (1321-1341).
